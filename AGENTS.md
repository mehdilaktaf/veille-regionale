# Agent Guidance: veille-regionale

## Developer Commands
- Run GUI App: `python app.py`
- Run headless CLI (un dépt/mois): `python run.py <dépt> <année> <mois> <dossier> [--max-wait S] [--delay S] [--refresh] [--max-docs N]`
- Probe a site (WAF/CDN + robots.txt, 1 GET): `python run.py <dépt> --probe`
- Run Analysis Script: `python analyse.py [chemin/vers/pdf.pdf]`
- Run PDF Fetcher (Standalone): `python fetch_and_merge_pdf.py`
- Run Tests: `python -m unittest`
- Python d'exécution : `.venv/bin/python` (déps dans `requirements.txt`)

## Dependencies & Setup
- Install requirements: `pip install -r requirements.txt`
- Aucun navigateur requis : les 21 départements (Pays de la Loire + outre-mer + Moselle + Aisne + Ardennes + Aube + Marne + Haute-Marne + Meurthe-et-Moselle + Meuse + Bas-Rhin + Haut-Rhin + Territoire de Belfort) passent en HTTP direct (Selenium retiré du projet).

## Architecture & Flow
- `app.py`: Main entry point. GUI for selecting department/year/month to automate scraping and merging of PDFs. Utilise `clients.build_client`.
- `clients.py`: Source de vérité partagée du mapping département → (URL, classe de client) : `DEPARTMENT_URLS` + `build_client(dépt, année)`. Importé par `app.py` (GUI) et `run.py` (CLI) pour ne pas diverger.
- `run.py`: CLI headless d'un dépt/mois : liste (mise en cache dans `<dest>/.raa_list/`), téléchargements avec reprise, puis fusion. Options : `--max-wait` (sonde 1 GET/min jusqu'au déblocage WAF), `--delay` (pacing), `--refresh` (re-calculer la liste), `--probe` (diagnostique WAF/CDN + robots.txt), `--max-docs N` (mode test : les N documents les plus récents du mois seulement, fusion partielle nommée `RAA_fusionne_partiel_...` — la liste complète reste en cache). Reprend un run interrompu (les PDF complets ne sont pas retéléchargés, la liste est en cache).
- `raa_client.py`: Base partagée : session HTTP (`RaaHttpClient`) avec **pacing** (délai min `request_delay` par défaut 2 s entre deux requêtes via `_throttle()`), **retry 4** dont un **cooldown 90 s** sur coupure de connexion/refus (signature du blocage WAF), **reprise** (`download` saute un PDF déjà complet `%PDF-`+`%%EOF`), téléchargement PDF avec contrôle d'en-tête, parsing de dates tolérant (`parse_month`/`parse_day_month`), extraction des dates ancrées sur « du » (`du_day_month`), lecture du span CMS (`link_day_month`), dédoublonnage par nom (`dedupe_documents`), filtrage/tri par mois (`select_month_documents`) et deux classes de patterns : `AnnualPageRaaClient` (page annuelle de liens directs) et `MonthCardsRaaClient` (cartes « Mois YYYY » vers des pages de liens, balayeur de toutes les pages de mois).
- `vendee_client.py`: Client HTTP du RAA de la Vendée, partagé par `app.py` et `fetch_and_merge_pdf.py`.
- `aisne_client.py`: Client HTTP du RAA de l'Aisne (cartes « RAA Année YYYY » → cartes documents paginées → page document, span CMS).
- `ardennes_client.py`: Client HTTP du RAA de l'Ardennes (sous-classe de `AnnualPageRaaClient`, année en cours directe ou via « années antérieures », page annuelle de liens directs, carte commune 2015 & 2016).
- `aube_client.py`: Client HTTP du RAA de l'Aube (cartes « RAA YYYY » → cartes documents paginées avec liens directs vers le PDF, date = attribut `title` CMS, pattern Loire-Atlantique).
- `marne_client.py`: Client HTTP du RAA de la Marne (2 flows : 2025-2026 menu **1 select par mois** + POST pattern Vendée ; 2013-2024 cartes groupes « Années A à B » → pages documents).
- `haute_marne_client.py`: Client HTTP du RAA de la Haute-Marne (sous-classe de `AnnualPageRaaClient`, cartes « Année YYYY » (2026→2017), page annuelle de liens directs sans pagination ; 2026 sans span CMS → date du nom de fichier, années anciennes avec span CMS).
- `meurthe_et_moselle_client.py`: Client HTTP du RAA de la Meurthe-et-Moselle (cartes « Recueils des actes administratifs année YYYY » (2026→2017) → page annuelle : select « Liste-liste-docs » + POST → panneau, pattern Vendée ; mois du libellé ancré « du » en pré-filtre, span CMS faisant foi).
- `meuse_client.py`: Client HTTP du RAA de la Meuse (sous-classe de `AnnualPageRaaClient` ; navigation par select d'années « Liste-des-recueils-liste-docs » 2026→2006 au lieu de cartes, values relatives à la racine du site ; page annuelle de liens directs, span CMS 100 %).
- `bas_rhin_client.py`: Client HTTP du RAA du Bas-Rhin (cartes « RAA ANNEE YYYY » sans accent (2026→2017) → page annuelle : **1 select par mois** tous nommés « Liste-liste-docs » + POST → panneau, pattern Marne/Vendée ; mois du dossier mensuel de la value en pré-filtre, span CMS faisant foi).
- `haut_rhin_client.py`: Client HTTP du RAA du Haut-Rhin (cartes d'années à texte exact « YYYY » (2026→1994, archive la plus profonde vue) → page annuelle de cartes documents paginées avec liens directs vers le PDF, date = attribut `title` CMS, pattern Aube/Loire-Atlantique).
- `territoire_de_belfort_client.py`: Client HTTP du RAA du Territoire de Belfort (sous-classe de `AnnualPageRaaClient` ; navigation par liens `a.fr-link` « Année YYYY » au lieu de cartes, page annuelle de liens directs sans pagination, span CMS 100 %).
- `calvados_client.py`: Client HTTP du RAA du Calvados (sous-classe de `AnnualPageRaaClient` ; 2 niveaux : section → carte « RAA départemental » → cartes années texte exact « YYYY » (2026→2018) + carte « Archives », page annuelle de liens directs ≈ 350/an sans pagination, span CMS 100 %).
- `eure_client.py`: Client HTTP du RAA de l'Eure (3 niveaux, pattern Aisne : cartes « RAA YYYY » (2026→2015) → page annuelle de cartes documents paginées par 10 (≈ 25 pages) → page document avec 1 lien `a.fr-link--download` + span CMS ; mois de la carte ancré « du » en pré-filtre, cartes à mois non détectable (typos « oaût », « febvrier ») visitées au balayeur, le mois CMS faisant foi).
- `maine_et_loire_client.py`: Client HTTP du RAA du Maine-et-Loire (sous-classe de `AnnualPageRaaClient`).
- `sarthe_client.py`: Client HTTP du RAA de la Sarthe (sous-classe de `AnnualPageRaaClient`).
- `mayenne_client.py`: Client HTTP du RAA de la Mayenne (sous-classe de `MonthCardsRaaClient`, deux layouts de page annuelle).
- `loire_atlantique_client.py`: Client HTTP du RAA de la Loire-Atlantique (page mensuelle paginée).
- `guadeloupe_client.py`: Client HTTP du RAA de la Guadeloupe (sous-classe de `MonthCardsRaaClient`).
- `guyane_client.py`: Client HTTP du RAA de la Guyane (sous-classe de `MonthCardsRaaClient`).
- `martinique_client.py`: Client HTTP du RAA de la Martinique (sous-classe de `AnnualPageRaaClient`, carte annuelle ou via « Archives », sous-pages RAA + spéciales).
- `mayotte_client.py`: Client HTTP du RAA de Mayotte (cartes mois → cartes documents paginées → page document, span CMS).
- `reunion_client.py`: Client HTTP du RAA de La Réunion (cartes RAA paginées → actes individuels — la Réunion ne publie pas de recueil composé).
- `moselle_client.py`: Client HTTP du RAA de la Moselle (site legacy `mc.moselle.gouv.fr` : recherche POST par date, tableau paginé, téléchargement par md5id).
- `fetch_and_merge_pdf.py`: Récupération + fusion des PDFs Vendée en standalone (utilise `vendee_client.py`).
- `analyse.py`: Extracts **bold text** from merged PDFs and searches for specific regional administrative keywords, exporting to Excel.

## Critical Quirks
- **Scraping Vendée**: sans Selenium. La page annuelle liste les documents dans `select#Liste-liste-docs` ; le lien de téléchargement est généré par un `POST` vers la même URL avec le champ `Liste-liste-docs` (voir `vendee_client.py`). Aucun cookie ni refus de bannière nécessaire. Le mois d'un document fait foi sur la date du panneau de téléchargement (`span.fr-link__detail`, générée par le CMS) : les libellés du menu comportent des fautes de saisie (`20/08/026`, `19//06/2026`, dates absentes) et ne servent que de pré-filtre ; les docs sans date au menu sont vérifiés au POST (« balayeur »). Politesse intégrée : pacing 2 s entre les POSTs (throttle de base) + retry 4 / cooldown 90 s sur blocage, timeout 60 s — ne pas diminuer ces délais (le site/proxy bloque les accès répétés).
- **Scraping Maine-et-Loire**: sans Selenium (pages statiques, pop-up tarteaucitron sans effet côté serveur). La carte « Année YYYY » mène à la page annuelle des liens `a.fr-link--download`. Le mois d'un document fait foi sur la date du `span.fr-link__detail` du lien (`PDF - 10,51 Mb - 28/08/2026`, générée par le CMS, présente sur 100 % des liens) : le nom de fichier (ancré sur « du », fautes tolérées `23062026`, `08 janvier`, ordinaux `1er`) ne sert que de contrôle croisé (désaccord → warning, le mois CMS fait foi). Les documents non-RAA postés sur la page (arrêtés) sont inclus si leur date CMS tombe dans le mois cible.
- **Scraping Sarthe**: sans navigateur, même structure que le Maine-et-Loire — cartes « Recueil des actes administratifs (RAA) - Sarthe - YYYY » vers la page annuelle des liens `a.fr-link--download` (≈ 186 liens/an), mois fait foi sur le `span.fr-link__detail` CMS.
- **Scraping Mayenne**: sans navigateur. La page annuelle `/Annee-YYYY` a deux layouts : cartes « Mois YYYY » (années récentes, page mensuelle) ou liens `a.fr-link--download` directs (années anciennes). Les noms de fichier ne portent jamais de date (`recueil-53-2026-183-...`) : la date vient du `span.fr-link__detail` CMS quand il est présent, sinon du texte du lien ancré sur « du » (« RAA spécial du 28 août 2026 », warning « non vérifié »). Un fichier peut être posté deux fois (ré-upload) : en cas de doublon de nom, l'entrée datée par le CMS est conservée.
- **Scraping Loire-Atlantique**: sans navigateur. Page mensuelle `/{année}/<slug-mois>/` (slug = mois non accentué, ex. `aout`) listant les cartes `a.fr-card__link.menu-item-link`, paginées par 10 via le lien « Suivant » (`(offset)/10`). La date fait foi sur l'attribut `title` de la carte généré par le CMS (`format pdf - 10,24 Mb - 28/08/2026`) ; le texte de la carte sert de contrôle.
- **Scraping Guadeloupe / Guyane**: sans navigateur, même pattern que la Mayenne (`MonthCardsRaaClient`) : page annuelle (…/YYYY ou …/Annee-YYYY) → cartes « Mois YYYY » → pages de liens `a.fr-link--download` avec span CMS 100 %. Toutes les pages de mois de l'année sont balayées (un doc daté du 02/02 peut être posté sur la page de janvier).
- **Scraping Martinique**: sans navigateur. Carte « RAA YYYY » sur la page publications, années antérieures sous la carte « Archives » (cartes « RAAP YYYY » / « R.A.A.P YYYY »). La page annuelle porte des sous-cartes (RAA + éditions spéciales) : les liens des sous-pages sont tous collectés, span CMS faisant foi.
- **Scraping Mayotte**: sans navigateur. Trois niveaux : cartes mois (majuscules, année parfois absente « FÉVRIER ») → cartes documents paginées par 10 (« n°001 du 05 janvier 2026 ») → page document avec 1 lien `a.fr-link--download` + span CMS (source de vérité) ; le texte de la carte sert de contrôle.
- **Scraping La Réunion**: sans navigateur. La Réunion ne publie pas de recueil composé : la page annuelle (paginée par 10) liste des séparateurs de mois (cartes « AOUT » sans date, absents pour le mois le plus récent) et des cartes RAA (« Spécial n° 169 du 27 août 2026 ») menant à la page des actes individuels (span CMS 100 %). Le « fusionné » de La Réunion = fusion des actes du mois (texte de carte = pré-filtre du mois).
- **Scraping Moselle**: sans navigateur, site à part — les RAA sont sur le site legacy `mc.moselle.gouv.fr` (pas la plateforme CMS des préfectures ; la page www ne porte qu'une vue partielle 2024). Recherche POST (`raa.html?adminedit=1?tab=1&do=exec_search_rec`, champs `date_pub`/`date_pub_end` au format JJ/MM/AAAA, `date_pub_op=entre`, `type_acte=0`), résultats dans `table.table_list` (Type | Référence « Numéro 195 » | Date de publication | lien `docfile_md5id`), pagination via le lien « > » (`page=N`, critères en session — ne pas vider la session). La « Date de publication » du tableau fait foi ; le nom de fichier est dérivé : `RAA n°195 du 28-08-2026 (Spécial).pdf` (pas de `/` dans les noms). Les lignes de pagination du tableau doivent être ignorées (pas de « Numéro N » ni date).
- **Scraping Aisne**: sans navigateur. Trois niveaux : cartes « RAA Année YYYY » (page section, 2026→2010, coquilles de slug : 2018 → `RAA-Annee-20182`, 2012 en minuscule « RAA année 2012 ») → page annuelle listant les cartes documents `h2.fr-card__title` paginées par 10 (`(offset)/N`, ~17 pages) → page document avec 1 lien `a.fr-link--download` + span CMS (source de vérité). Le mois est codé dans le **nom de la carte** (`RAA_Aout_02-2026-120`, le 02 = n° de dépt) : `month_of_text` (raa_client.py) pré-filtre sur le nom avant de visiter la page document (économie de GETs). La carte « Sommaire RAA » n'est pas un document (exclue). Le nom de fichier (`recueil-02-2026-NNN-...`) ne porte aucune date.
- **Scraping Marne**: sans navigateur, 2 flows. **2025-2026** (pattern Vendée) : la page annuelle porte **un select par mois** — il n'y a pas de select global ; le select du premier mois est placé en tête de page avec un nom à double tiret (`Liste-des-RAA--liste-docs`), les autres à tiret simple (`Liste-des-RAA-liste-docs`). La liste de l'année = union des options de tous les selects (dédoublonnées par value) ; le mois fait foi sur le **dossier mensuel de la value** (`Media/Files/Prefecture/RAA/2026/Fevrier/...`) et le libellé (« RAA n°51-2026-040 du 27 février 2026 ») confirme. Le POST de la value avec le champ du dernier select génère le panneau (a.fr-link--download + span CMS faisant foi) ; le nom de fichier généré (`recueil-51-2026-040-...`) ne porte aucune date — la value non plus si son slug est muet (ex. `RAA-n-51-2026-041` sans dossier mois ni « du ») : ces options sans mois détectable sont POSTées au balayeur, le mois CMS faisant foi. **2013-2024** : la page section porte la carte « 2024 » (texte exact, jamais de match partiel — « Années 2013 à 2016 » contient « 2016 ») et des cartes de groupes (« Années 2021 à 2023 » → cartes « RAA Année YYYY », coquille « RAA  Année 2022 » double espace) ; la page annuelle est un tableau de liens vers des pages documents (« Recueil n°2-1 du 1er février 2024 »), le mois du libellé (ancré « du ») pré-filtre avant le GET de la page document (span CMS faisant foi) ; un doc « du 31 janvier » publié le 03/02 peut être manqué (documenté au catalogue).
- **Scraping Aube**: sans navigateur. Cartes « RAA YYYY » (2024→2026, pas de carte archives visible) → page annuelle de cartes documents paginées par 10 (`(offset)/N`, « Suivant ») : chaque carte est un **lien direct vers le PDF** (`a.fr-card__link.menu-item-link`, pas de page document intermédiaire). La date fait foi sur l'attribut `title` de la carte généré par le CMS (`format pdf - 2,57 Mb - 31/08/2026`, même pattern que la Loire-Atlantique) ; le texte (« RAA n°207 du 31 août 2026 ») sert de contrôle. Les noms CMS comportent des coquilles de mise en forme (« RAA  n°47 » double espace, « RAAn°049 » sans espace) — sans impact.
- **Scraping Ardennes**: sans navigateur, même pattern que le Maine-et-Loire (`AnnualPageRaaClient`). La page section porte la carte de l'année en cours et, pour les années antérieures, une carte « années antérieures » (2025 → 2017 + carte commune « des années 2015 & 2016 »). La page annuelle liste ≈ 288 liens `a.fr-link--download` sans pagination, span CMS 100 % faisant foi. Le nom de fichier (« RAA 8-2026-144 du 31 aout 2026.pdf ») sert de contrôle mais son préfixe (le 8) peut diverger de la date CMS (ex. « RAA 8-2026-033 du 19 janvier 2026 » daté CMS février) — ne jamais utiliser le préfixe comme mois. La carte commune 2015 & 2016 mélange deux années : le filtrage par mois ne distingue pas l'année (à gérer au backfill).
- **Scraping Haute-Marne**: sans navigateur, même pattern que le Maine-et-Loire (`AnnualPageRaaClient`). Cartes « Année YYYY » (2026→2017, pas de carte archives visible) → page annuelle de liens directs sans pagination. **2026** : liens `a.fr-link` plain (URL absolue, **sans span CMS**) — la date ne vient que du nom de fichier, coquilles tolérées (année sur 2 chiffres « RAA n° 19 du 05-02-26.pdf », tiret final « RAA n° 21 du 02-03-2026-.pdf ») : `AnnualPageRaaClient` essaie d'abord `du_day_month(name)` (ancré « du », normalise les tirets bas), puis `relaxed_day_month`. **Années anciennes (2017)** : liens `a.fr-link--download` + span CMS (source de vérité).
- **Scraping Meurthe-et-Moselle**: sans navigateur, même pattern que la Vendée. Cartes « Recueils des actes administratifs année YYYY » (2026→2017, pas de carte archives visible) → page annuelle portant un select « Liste-liste-docs » (1 option par document, placeholder « Liste », libellés « Numéro N du D mois YYYY ») : le POST de l'option vers la même page génère le panneau de téléchargement (`a.fr-link--download` + `span.fr-link__detail` CMS faisant foi). Le mois du libellé (ancré « du », 100 % des options 2026 datables) pré-filtre avant le POST ; les options sans date détectable sont vérifiées au POST (« balayeur »). Les liens `a.fr-link` plain de la page (accessibilité « Aller au contenu » etc.) ne sont pas des documents.
- **Scraping Meuse**: sans navigateur, page annuelle de liens directs (`AnnualPageRaaClient`) avec span CMS 100 % — mais la page section ne porte **pas de cartes années**, un select « Liste-des-recueils-liste-docs » (2026→2006). Les **values des options sont relatives à la racine du site** (« Publications/... », sans barre initiale) : il faut ajouter la barre initiale avant `urljoin`, sinon le préfixe de la page section est dupliqué (`/Publications/Publications/...` → 404). Coquille de casse réelle : 2020 est « RAA **A**nnée 2020 » (la comparaison des libellés est insensible à la casse).
- **Scraping Bas-Rhin**: sans navigateur. La section est sous « Publications officielles » ; cartes « **RAA ANNEE YYYY** » en majuscules **sans accent** (2026→2017) — `find_annual_href` est insensible à la casse, aux accents (unidecode des deux côtés) et aux espaces multiples. La page annuelle porte **un select par mois** (9 selects 2026, tous nommés « Liste-liste-docs » — sans la coquille double tiret du 1er select Marne) ; la liste de l'année = union des options de tous les selects (dédoublonnées par value). Le mois fait d'abord foi sur le **dossier mensuel de la value** (`Media/Files/22.-RAA/2026/Fevrier/...`), le libellé (« RAA N° X du D mois YYYY », ancré « du ») en contrôle ; le POST génère le panneau (a.fr-link--download + span CMS faisant foi).
- **Scraping Haut-Rhin**: sans navigateur, même pattern que l'Aube / la Loire-Atlantique. La page section porte des cartes d'années à **texte exact « YYYY »** (2026→1994, archive la plus profonde vue en Grand Est — jamais de préfixe « RAA ») : la navigation est un match exact sur le texte de la carte, jamais partiel. La page section peut porter un **lien PDF égaré dans une carte** (« Reccueil n°77 du 10 juillet 2026 » — coquille du site) : ignoré car le texte de la carte n'est pas une année. La page annuelle liste des cartes documents paginées par 10 (`(offset)/10`) dont le lien (`a.fr-card__link.menu-item-link`) pointe **directement sur le PDF** ; la date fait foi sur l'attribut `title` CMS (`format pdf - 1,02 Mb - 31/08/2026`), le texte de la carte (« Recueil n°100 du 31 août 2026 ») servant de contrôle.
- **Scraping Calvados**: sans navigateur. Navigation à 2 niveaux : la page section porte les cartes « RAA départemental »/« régional » ; la page départementale porte les cartes années à texte exact « YYYY » (2026→2018) et une carte « Archives ». La page annuelle liste ≈ 350 liens `a.fr-link--download` directs sans pagination, span CMS 100 % faisant foi ; les noms de fichier (`recueil-14-2026-369-...`) ne portent aucune date. Des AP non-RAA peuvent être postés sur la page annuelle : ils sont inclus si leur date CMS tombe dans le mois cible (règle M49).
- **Scraping Eure**: sans navigateur, même structure 3 niveaux que l'Aisne. Cartes « RAA YYYY » (2026→2015, pas de carte archives visible) → page annuelle de cartes documents paginées par 10 (« Recueil spécial N°27-2026-261 du 01 septembre 2026 ») → page document avec 1 lien `a.fr-link--download` + span CMS (source de vérité). Le mois de la carte (ancré « du ») pré-filtre **avant** le GET de la page document (économie de req) — mais le site porte des **typos de mois** (« du 14 oaût 2026 », « du 28 febvrier 2026 » : la transposition « febvrier » n'est pas dans la liste des mois) : les cartes à mois non détectable sont visitées au « balayeur », le mois CMS faisant foi (une carte typo « febvrier » n'est pas à exclure du pré-filtre). La page section porte des **cartes documents parasites** (« Recueil spécial n°27-2026-217 du 10 juillet 2026 », slug coquille se terminant par « 20262 ») : `find_annual_href` ne matche que le texte exact « RAA YYYY ».
- **Scraping Territoire de Belfort**: sans navigateur. Domaine `www.territoire-de-belfort.gouv.fr` (`belfort.gouv.fr` ne résout pas). La page section ne porte ni cartes ni select : des liens `a.fr-link` plain « Année YYYY » (2026→2015 + 2010, 2011-2014 absents ; **coquille réelle : « Année 2021 » pointe sur la page Annee-2022**) — navigation par match exact sur le texte du lien. Slugs longs pour 2023+ (…/Le-recueil-des-actes-administratifs-Annee-2026), courts pour 2015-2022 (…/Annee-YYYY). La page annuelle liste des liens `a.fr-link--download` directs sans pagination, span CMS 100 % faisant foi (pattern `AnnualPageRaaClient`). Les noms de fichier sont ancrés sur « publié le » (pas « du ») avec double espace (« recueil-90-2026-014- publié le 02-02-2026.pdf ») : le repli `relaxed_day_month` de la base suffit. Le span CMS (date de dépôt) peut diverger du nom (warnings) — le CMS fait foi.
- **Organisation des fichiers** : les PDF individuels vont dans `<dest>/<département>/<année>/<mois>/` et le PDF fusionné (`RAA_fusionne_<mois>_<année>_<département>.pdf`) dans `<dest>/<département>/`. Les clients retournent les documents en ordre chronologique croissant (jour d'abord, nom en second) — ne pas réordonner avant la fusion.
- **Analysis Path**: `analyse.py` accepte le PDF en argument (`sys.argv[1]`), sinon chemin Windows par défaut à remplacer.
- **Timing / blocage WAF**: tout en HTTP direct. Les WAF des sites préfecture (partagent la même plateforme CMS, mais le blocage est **par IP et couvre tout `*.gouv.fr` préfecture**) coupent la connexion sans réponse (`RemoteDisconnected`) quand le **volume de requêtes sur une fenêtre glissante** dépasse un seuil non public (~30–50 req ; mesuré : un run ~27 req passe, l'enchaînement de deux runs bloque). Ce seuil n'est documenté nulle part (pas de `robots.txt`/Crawl-delay, WAF non identifiable par les en-têtes — voir `run.py <dépt> --probe`). `RaaHttpClient` intègre : **pacing** 2 s entre requêtes (`_throttle`), **retry 4 / cooldown 90 s** sur coupure (traverse un à-coup), **reprise** (ne retélécharge pas un PDF complet). `run.py` ajoute la **cache de liste** (la coûteuse phase de liste ne se fait qu'une fois, `<dest>/.raa_list/`) et `--max-wait` (sonde 1 GET/min jusqu'au déblocage, sans insister). Conséquences : un dépt à la fois, **un run complet par fenêtre WAF** ; si le blocage s'installe (cooldown long, 30–60 min, auto-entretenu par de nouveaux essais), attendre au lieu d'insister, puis relancer (la reprise + la cache rendent la relance rapide). Ne pas diminuer les délais.
